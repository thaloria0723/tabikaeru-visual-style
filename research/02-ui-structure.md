## 2. 逐个界面的构成

### 2.1 にわさき（庭院）—— 首页

**屏幕内容（自上而下 / 由远及近）**
- 背景：房子的外观 + 前院，画面为**全屏插画，无顶部 HUD 条、无底部导航栏外框**。【查证：多个来源描述主界面只有两个主场景，按钮以图标形式存在】[1][3][8]
- 田地：随时间长出三叶草（みつ葉），**左右滑动（swipe）收割**，不是点击收割。[8][2]
- 信箱（ポスト）：有信时出现提示。[1]
- 访客：蜗牛 / 蜜蜂 / 乌龟等随机来访，可用特产投喂。[1][12]
- 青蛙本体：在家时出现在场景里，**可以被点击**（改名/看称号）。[12]

**按钮（贴边浮在场景上，不占独立栏位）**【查证】
- **左下角 = したく（树/木枝图标）** → 进入准备行李 [8]
- **右下角 = おうち（房子图标）** → 进入室内 [8]
- **右下角一带 = おみせ（蓝白布包图标）** → 进入商店 [8]
  - 【存疑】此处来源表述含糊，商店按钮究竟在「庭院屏右下」还是「室内屏右下」我未完全确认；日文攻略倾向为**从室内进入商店**（见 2.2）。
- **玄关的门也可点击进入室内**（1.1.0 版本后追加）。[8]

**占比**：插画约占屏幕 100%，UI 按钮是很小的角标，估算合计占屏 <10%。【推断：占比数字未查到实测值】

**布局逻辑**：按钮**贴左右下角**，不居中、不排成一行。用意是拇指区。【推断】

### 2.2 おうち（室内）

**屏幕内容**
- 带阁楼的小房间：下方是起居区（一桌一椅一柜），云形螺旋楼梯，上方是蓝色床铺。【1】
- 青蛙在家时随机做活动：读书、吃饭、写信、木工、睡觉、喝咖啡。【3][12]
- **のれん（暖帘）** 可以点击 → 直达「ずかん」「アルバム」的快捷方式。【8][11]
- 有**收音机（ラジオ）**可开。【6][8]

**按钮**
- **左下角 = 原木色木头按钮** → したく（准备行李）。【查证：多个中文攻略明确"点击木头"】[1][4]
- **右下角 = 蓝白布包** → おみせ（商店）。[1]
- **右上角 = メニュー**。【查证】[12]
- 【存疑】菜单在「庭院」还是「室内」，不同来源说法不一，有来源称"庭院内上方为主菜单"，也有称"室内右上是菜单"。可能两者都有入口。

### 2.3 したく（准备行李）—— 全屏独立 UI 屏，双页结构

这是**整个游戏里唯一有明确"界面背景色"的地方**，也是 UI 层与场景层分离最明显的地方。

**かばん（背包）页 —— 蓝色背景**【查证】
- 槽位布局：**左上 = おべんとう（便当）、右上 = おまもり（护身符）、下方 = どうぐ（道具）**，共 3 个槽。【查证：中文与日文来源一致】[4][8]
- 底部有 **白色的「かんりょう」（完成）按钮** → 锁定。再按一次解除锁定。出发前可反复更改。[4][8]
- 语义：这里放的东西是**下一次旅行必定带走的**。[1]
- 便当是**必需品且一次性消耗**；护身符一次性；道具永久。[8]

**つくえ（桌子）页 —— 黄色背景**【查证】
- **同样 3 个槽位，与背包一一对应**。[8]
- **没有确认按钮** —— 放进去即生效，不需要按完成。[1]
- 底部有 **「かたづける」（收拾）按钮** → 清空桌面，物品返回「もちもの」（不是删除）。[4][8]
- 语义：备用品。**如果背包是空的，青蛙会自己从桌上随机拿东西带走**。[1]

**两页之间的切换**：背包框右边的小三角点开可进入桌子页。【查证】[1]

> 关键设计：**用背景色区分两种"容器"语义**——蓝色 = 一定会带走，黄色 = 备用。
> 颜色在此承担**语义编码**而非装饰功能。【查证：多个来源都把"蓝色页面/黄色页面"作为第一标识来讲】[1][4][8]

### 2.4 おみせ（商店）

**屏幕内容与布局**
- 商品以**分页**方式排列，需要翻页（不是一屏长滚动列表）。【查证】[10]
  - 第 1 页：食物（便当）
  - 第 2 页：第一行食物，第二行第一个是护身符，之后是手ぬぐい（布巾/道具）
  - 第 3 页：第一行布巾，第二行起帐篷
  - 第 4 页：第一个帐篷，其余是器（碗，乘船用）
  - 最后一页：灯（蜡烛、提灯、灯笼）
- **右上角 = ふくびき（抽奖）入口**。【查证】[10]
- **购买操作：点击物品两下**即可购买。【查证】[10]
- **已购买的非消耗品会显示红色「售罄」标签**。【查证】[10] ← 这是很有代表性的"纸片/标签"式状态标记
- 商品说明文字**刻意只给暗示，不给具体数值**（开发者明说）。[1]
- 价格体系：10 / 20 / 50 / 80 / 100 / 150 / 250 / 300 / 400 / 450 / 500 / 600 / 700 / 750 / 900 / 1000 / 1200 / 1500 / 3000 三叶草。[10]

### 2.5 ふくびき（抽奖）

- **5 张抽奖券抽一次**。[1][3]
- 奖品：金の玉 = 直通各方位特殊车票；赤い玉 = 金平糖等；一次性。[1]
- **视觉形态是「和风的抽奖轱辘/摇奖机」**；淘宝中国版把它换成了中国风的摇奖盘。【查证】[19][20]

### 2.6 うらべや（里屋）/ ずかん（图鉴）/ アルバム（相册）

- 入口：室内右上菜单 → うらべや；或点室内的**のれん**直达。[8][11]
- **ずかん（图鉴）**：分「いっぴん」（珍稀掉落 / 珍品）与「めいぶつ」（名物 / 特产目录）。**开过即永久保存**。[1][5]
- **アルバム（相册）**：**初始容量 6 张 × 12 页 = 72 张**。可用 300 三叶草增加 2 页。照片**可删除**（图鉴不可删）。[5][11] ← 这个"6×12 页"是查证到的明确网格参数
- 照片可保存 / 转发 / 删除。[11]

### 2.7 もちもの（现有物品）

- **4 个分类标签页：おべんとう（便当）/ どうぐ（道具）/ おまもり（护身符）/ めいぶつ（特产）**。【查证】[1][10][12]

### 2.8 メニュー / ヘルプ / オプション

- 菜单项：**うらべや（图鉴与相册）、帮助、玩法介绍、声音设置、画面适配**。[1][12]
- **设置里有「屏幕适配」滑杆**（帮助 → 选项 → 屏幕适配），可调界面显示大小。**1.13.0 版本确认存在**。【查证】[13]

### 2.9 起名 / 改名 / 称号

- 首次进入需给青蛙取名，**最多 5 个字**（开发者预期是汉字输入，所以限 5 字）。【查证】[7]
- 青蛙在家时可点击它改名、变更「称号」。[12]

### 2.10 信箱

- 信件类型：青蛙来信（带照片）、访客回礼、**系统广告**。[1]
- **广告不点击会自动消失**。【查证】[1]
- 断网时提示，可在网络好的地方反复点击重试。[1]

### 2.11 启动页与首次引导

- **首次流程**（查证到一条较完整的）：启动 → 点「開始」→ 同意规则 → 给青蛙取名（≤5 字）→ 进屋，出现**白色小手提示** → 按提示准备便当/护身符/道具 → 到庭院，白手提示**向左滑动屏幕**收割三叶草 → 进商店点两下买东西 → 回家把东西放进背包和桌子空格 → **部分版本需要重启一次游戏**青蛙才会出发。[14]
- 【存疑】关于"有没有教程"来源冲突：一说**没有游戏指引**，玩家靠外部攻略；一说有**约 3 分钟教程**。可信的折中是：**引导极简，仅靠"白色小手"局部提示，没有对话、没有文字教学页**。[14]

## 3. 信息密度

**结论：极低，且明显有"一屏只做一件事"的倾向。**

| 界面 | 一屏同时呈现的信息 | 来源/说明 |
|---|---|---|
| にわさき | 三叶草数量 + 信箱有无信 + 有无访客 + 青蛙在不在家。**就这些** | [1][3] |
| おうち | 青蛙在做什么（一个动作）+ 几个角落按钮 | [3][12] |
| したく/かばん | **3 个槽位 + 1 个确认按钮** | [4][8] |
| したく/つくえ | **3 个槽位 + 1 个收拾按钮** | [4][8] |
| 商店 | 一页约 5–6 件商品（分页而非长列表） | [10] |
| まとめ もちもの | 4 个标签，每次只看一类 | [10] |
| 相册 | 一页 6 张 | [11] |

**证据性判断**
- 【查证】有评测直接用"**像两页漫画**"来形容这个游戏的界面结构。[1]
- 【查证】评测称其为典型日系"性冷淡风"，主界面只有"家"和"前院"两个主场景。[9]
- 【推断】商店刻意用**分页**而不是滚动列表，是"一屏一件事"的具体落地手法：分页天然限制单屏项数，也让"翻页"这个动作本身成为节奏的一部分。

**列表项之间如何区分**（这是设计中信息量最大的一处）
1. **分类靠独立标签页 / 独立分页**，而不是靠列表内分组标题 —— 即**用"切换"代替"层级"**。[10]
2. **消耗品 vs 永久品**靠**红色「售罄」标签**区分（买过就贴标签）。[10]
3. **语义靠背景色**：蓝 = 背包（必定带走），黄 = 桌（备用）。[1][4][8]
4. 单项信息只有：**图标 + 名称 + 价格**。说明文字只给模糊暗示。[1][10]

## 4. 控件形态

### 4.1 主场景：按钮 = 场景里的物件（拟物 / 半叙事化）

| 功能 | 按钮形态 | 来源 |
|---|---|---|
| したく（准备） | **原木色木头 / 树枝** | [1][4][8] |
| おうち（进屋） | **房子** | [8] |
| おみせ（商店） | **蓝白布包** | [1][8] |
| うらべや | **のれん（暖帘）** | [8][11] |

【查证】这些都是"世界内的物件"而不是标准 UI 控件。**没有查到这些按钮有描边、圆角矩形底板或阴影边框**。[1][4][8]
【推断】它们的可点击性靠"被画得很清楚的独立小物件 + 位于屏幕角落 + 白色小手引导"来传达，而不是靠按钮外观。

### 4.2 功能屏：极简槽位 + 单色底

- 背包/桌子：**3 个槽位组成的框**（左上、右上、下方），**槽位本身就是唯一的"列表"**。[4][8]
- 确认类按钮：**白色「かんりょう」（完成）按钮，位于画面下方**。没有查到它有边框/图标的描述。[4][8]
- 状态标记：**红色「售罄」标签**（纸质标签感）。[10]
- 抽奖：**和风摇奖轱辘**（机械拟物）。[19]

### 4.3 与"标准移动端 UI"的对比（推断）

【推断】这套 UI 里**几乎找不到典型的移动端控件**：
- 没有汉堡菜单、没有顶部标题栏、没有底部 Tab Bar、没有卡片列表、没有圆角矩形主按钮（除了那颗白色完成键）。
- 取而代之的是：**角落物件 + 槽位 + 单色底 + 标签**。
- 结果是"UI 不像 UI"，玩家感知上更像在"摆弄一个盒子里的东西"。

## 5. 文字层级

**【重要：本节查证不足，请谨慎使用】**

**查证到的**
- **原版只有日文，且主界面"全部是假名，一个汉字都没有"**（中文评测原文），非日语玩家"猜都没法猜"。[9]
- 名字输入限制 **5 个字符**。[7]
- 商品说明**刻意只给暗示不给具体数值**（开发者明说）。[1]
- 文本量极小：界面文字主要是**短名词**（便当、道具、护身符、特产、图鉴、相册、商店、家里）。[1][12]
- 有汉化攻略专门做"全界面中文翻译"，说明文字总量少到**可以整篇翻译**。[12]

**未能查证到的（明确标为空白）**
- ❌ 具体字号层级数、字号 px 值
- ❌ 字体族（是否手写体 / 圆体 / 明朝体）
- ❌ 文字是否有底板、描边、阴影
- ❌ 对比强度（拉开档次 vs 接近）

**我基于其他事实的推断**
- 【推断】由于文字几乎全是 2–4 字的短名词，且一屏同时出现的文字条目通常不超过 6 条，**这套 UI 很可能只需要 1–2 个字号层级**，依靠位置和颜色而非字号来建立层级。
- 【推断】文字放在插画/单色底上（蓝底、黄底、米色底），**底色本身已经提供了对比保障**，因此可能不需要额外的描边/阴影。这是相对安全的推断，但**未经截图确认**。
- 【推断】"只有假名、没有汉字"本身就是一种**降低视觉复杂度**的手段——假名字形简单、笔画少、视觉重量均匀，在低分辨率小字号下比汉字更不容易糊成一团。

## 6. 【重点】UI 与场景的关系

**这是本作 UI 最有辨识度的地方。结论：分层处理，不是单一策略。**

### 6.1 三个层次

**层次 A：主场景 = 插画本身，按钮浮在场景里（贴边角标）**

- 【查证】にわさき 和 おうち 是**全屏插画**，玩游戏时你看到的就是一幅画，按钮是画上的小物件。[1][3][8]
- 【查证】中文评测称其结构"像两页漫画"。[1]
- 【查证】按钮位置：**左下、右下、右上角落**，不在底部排成一条固定栏。[1][4][8]
- 【查证】**没有底部固定导航栏** —— 这是关键区别。你不在"菜单里"，你在"院子里"。
- 商店/抽奖/图鉴 都不是从底部栏进的，而是**从场景里的物件进**（布包、暖帘）。

**层次 B：功能屏 = 独立 UI 屏，用单色底切走**

- 【查证】したく（背包蓝底 / 桌子黄底）是**独立全屏界面**，不叠在插画上。[1][4][8]
- 【查证】商店、图鉴、相册也是独立界面。[1][12]
- 【推断】这是必要的妥协：3 个槽位 + 完成按钮的东西如果硬叠在插画上，会毁掉画面的完整性。

**层次 C：过渡（转场）**

- 【查证】**没有查到任何关于转场动画、加载动画、过场演出的资料**。这是一个明显的资料空白。
- 【推断】考虑到：① 界面全部是静态插画 + 少量小图；② 游戏体积小、纯本地；③ 团队只有 7 人；④ 整体是"慢"的调性 —— **转场很可能是直接切换或极短淡入，不会有花哨的过场**。但这属于推断，不要当作事实引用。

### 6.2 关键区分：**它同时是"叠在场景上"和"切到独立屏"，而且这个分工本身是设计**

| | 主场景层 | 功能层 |
|---|---|---|
| 呈现方式 | 全屏插画 + 角标物件 | 独立屏 + 单色底（蓝/黄/米） |
| 参与的动作 | "看" + "点一下"（收割、进屋、开信） | "整理" + "决策"（选什么、买什么） |
| 出现频率 | 90% 以上的打开时间 | 短促、间歇 |
| 情感角色 | 陪伴 / 观察 | 操作 / 计划 |
| 按钮形态 | 世界内物件 | 槽位 / 标签 / 白色按钮 |

【推断】这个分工的核心好处：
- **主场景永远不被操作面板侵占** → 打开 App 的第一眼永远是"一幅画 + 一只青蛙"，而不是"一个游戏主界面"。这是"治愈感"的来源。
- **一旦进入功能屏，就等于进入了"另一件事"**，语义清晰，不会和"正在陪伴青蛙"混淆。

### 6.3 为什么这对体验很重要（有来源支持的部分）

- 【查证】开发者明确：**不让玩家和青蛙对话/交流**，以此给玩家保留想象空间；青蛙的人设也不固定，由玩家自行补全。[16]
- 【查证】玩家被定位为**旁观者 / 父母式角色**，而不是操控者；没有即时反应和多余交互。[18]
- 【查证】玩家大部分游戏时间花在"期待"上，而不是操作上。[18]
- 【推断】如果主界面是传统手游的"顶栏 + 底部五连 Tab + 红点"形态，这套"旁观者"心理会立刻崩掉——**红点和横幅会把它变回"一个待完成的任务清单"**。所以"UI 叠在场景里、不切独立屏、不放底部栏"不是风格选择，而是**服务于情感目标的必然结果**。

## 7. 交互与反馈

### 7.1 点击反馈
- 【查证】**没有查到关于"按下变暗/缩放"等具体点击视觉反馈的描述。**
- 【查证】已确认存在**声音设置项**（菜单里有声音设置），且游戏有收音机道具。[12][6]
- 【推断】考虑到游戏整体的克制程度，点击反馈很可能**极轻**（无缩放弹跳、无明显高亮），但这是推断。
- 【查证】**小屏/部分机型会出现界面放大、文字和 UI 被裁切的问题**（商店评论）。[21]
- 【查证】广告点击不看会自动消失（即"忽略"是被允许的默认路径）。[1]

### 7.2 交互动作清单（很少）
【查证】玩家能做的全部动作：
1. **滑动**收割三叶草 [2][8]
2. 点击物件进出场景 [8]
3. 点击放行李、点白色「完成」锁定 [4][8]
4. 商店里**点两下**购买 [10]
5. 用特产投喂访客 [1]
6. 点开信箱看信 / 存照片 / 删照片 [1][11]
7. 改名字 / 改称号 [12]

### 7.3 刻意"慢"的设计（这是本作的核心机制，不是 UI 缺陷）

【查证】开发团队自述：市面上普通放置游戏太没意思，所以《旅行青蛙》本质上是**"用户被放置"（玩家被放置）**的游戏 —— 让玩家**享受等青蛙回家的过程**，用"思念"形成互动。[18]

【查证】具体证据：
- 点击**不会立刻产生可见奖励**；奖励以"明信片、特产、回家"的形式**延迟出现**，且**随机**（不知道去哪、不知道何时、不知道带什么）。[18]
- 青蛙何时出发、去哪、寄什么照片、何时回来，**全都不可控**，玩家无法交流也无法指挥。[18]
- 单次旅行最长可达约 4 天。[16]
- 首次旅行约需 1 小时。【查证】[1]
- 三叶草生长与上限：一说约 **4 分钟 1 个、上限 20 个**（约 80 分钟收一次最理想）；另一说约 **3 小时长满**。**两者冲突，标为【存疑】**。[1]

【查证】这套"强制等待 + 延迟满足"的原理与《Lifeline》同源：用真实时间同步的等待，把 Push 通知变成虚拟世界与现实世界的连接。[18]

【查证】代价（同样有来源）：缺少即时正向反馈、缺少成就感/挑战/社交，导致长期留存动力不足——场景单一、互动性差、控制感弱、无社交链。[18]

### 7.4 Push 通知
【查证】与《Lifeline》类比的分析明确指出 Push 通知承担了"连接虚拟与现实"的角色。[18]
【推断】通知是本作事实上的"UI 的一部分"——因为 app 内没有即时反馈，**在 app 外的时间才是主战场**。

## 8. 移动端约束

### 8.1 屏幕方向
- 【查证】游戏为**竖屏**（中文资料以"竖屏"讨论，且界面是单一纵向场景；攻略中的"屏幕适配"问题也出现在手机竖握语境）。[13]
- 【存疑】我未找到官方明写"portrait only"，但所有描述都是单列纵向场景，可视为竖屏。
- 【推断】竖屏 + 全屏插画 = **不需要处理横竖屏切换**，进一步降低复杂度。

### 8.2 单手操作区
【查证】主场景按钮位于**左下、右下、右上角落**。[1][8]
【推断】左下 + 右下正好覆盖左右手拇指的自然活动半径；**右下角放最高频的「进屋」**（因为进屋才能准备行李），符合单手习惯。
【推断】画面中央、上部**不放任何可点控件**（除了青蛙本体和のれん这类"世界内物件"），意味着**顶部区域对单手不可达的问题被直接绕开了**。这是一个很聪明的做法：不是把控件往下挪，而是**只在可达区放控件**。

### 8.3 安全区 / 分辨率适配
- 【查证】设置里有**「屏幕适配」滑杆**（帮助 → 选项 → 屏幕适配），可手动调节界面显示大小。版本 1.13.0 确认。[13]
- 【查证】部分安卓/鸿蒙设备上**游戏无法全屏**，社区回复称需开发者**增加分辨率支持**，"安卓不像鸿蒙那样自适应分辨率"。[22]
- 【查证】商店评论提到：**某些机型上游戏看起来被放大、文字和 UI 被裁切**。[21]

【推断】这说明本作采用的是**固定设计尺寸 + 用户可调的整体缩放**方案，而不是自适应布局：
- 优点：插画构图永远不被破坏，画面比例完全可控（对"当作一幅画看"的游戏是刚需）。
- 代价：**高/宽比异常的机型会出现留白、裁切或放大**，这正好解释了上面两条负面反馈。
- 【推断】安全区（刘海/挖孔/手势条）大概率就是靠整屏缩放后留边来被动规避，**没有做过系统性的 safe area 适配**。

### 8.4 小程序 / H5 适配版本
- 【查证】**日文原版没有官方小程序或 H5 版本**。[16][21]
- 【查证】**中国版《旅行青蛙·中国之旅》由阿里/淘宝获得授权，以淘宝内嵌小游戏 / 淘宝小程序形式存在，不是独立 App**（淘宝 App 内搜索"旅行青蛙"进入；官方当时表示暂不考虑独立 App）。[19][20]
- 【查证】中国版界面差异：
  - 总体延续原版界面和核心系统，**文字、菜单、物品说明全面中文化**，图片素材重新定制。[19][20]
  - 场景加入中国风：蒸笼、铁锅、笼屉、屏风、竹梯、灶台；庭院植物也不同。[19][20]
  - **摇奖界面由和风摇奖轱辘改为中国风摇奖盘**。[19]
  - 明信片换成中国景点（天坛、长城、孔明灯、高架桥）；特产换成"京味点心""兔儿爷"等。[19][20]
  - **新增「任务 / 活动 / 商城」三块内容**，可做任务领奖并兑换三叶草。[19][20]
  - **没有直接氪金系统**，三叶草主要通过活动/任务获取；金叶子可兑换三叶草。[19][20]
  - **去掉了原版抽奖券页面里的广告**；但也**缺少原版那种可随时查阅的教程说明**。[19][20]
- 【查证】中国版的技术/交互差异（对做小程序很有参考价值）：
  - **不能随意按安卓后退键** —— 按了会直接退出游戏回到淘宝 App，返回上一界面只能用游戏内按钮。[19]
  - 需要登录淘宝账号并联网；网络异常要求刷新（原版可离线、无需登录）。[19]
  - 不能与淘宝同时运行，玩游戏时收到旺旺消息必须退出游戏。[19]
  - 数据多存于线上，原版的修改/作弊方法较难生效。[19]
  - **淘宝行为会影响游戏机制**（加快三叶草生长、加快青蛙回来）。[19]

【推断】中国版加"任务/活动/商城"是对原版"低留存"缺陷的直接补丁，但**这恰恰破坏了原版 UI 最核心的克制感**；如果目标是复刻原版的体验，这部分**不应该照抄**。

## 9. 这套 UI 的设计原则提炼

> 每条都附在游戏里观察到的证据。前 6 条**可迁移性强**，最后 2 条**强依赖本作的特殊设定，迁移需谨慎**。

### 原则 1：把主界面做成"一幅画"，UI 只以角标物件存在，绝不加底部导航栏
**证据**：にわさき 与 おうち 是全屏插画；按钮是贴左下/右下/右上角的独立小物件（木头、房子、布包、暖帘）；**没有顶部标题栏、没有底部 Tab Bar**。[1][3][8]
**迁移方法**：把一个高频主页设计成完整场景，只允许 2–4 个"世界内物件"作为入口，且全部放在屏幕下半的可达区。

### 原则 2：一屏只做一件事；用「切换」代替「层级」
**证据**：一屏 3 个槽位 + 1 个按钮；商店用**分页**而非长列表；もちもの 用 4 个标签页而非树状分类；调色板式的"分类靠翻页"。[4][8][10]
**迁移方法**：当单屏项数超过 6–8 个时，优先考虑分页/标签，而不是加滚动条和分组标题。

### 原则 3：让颜色承担语义，而不是装饰
**证据**：**蓝色界面 = 背包（一定带走）**，**黄色界面 = 桌子（备用）**；这两个颜色是全游戏最稳定的语义锚点，所有攻略都以此作为第一说明。[1][4][8]
**迁移方法**：给每个功能态分配唯一且不变的颜色，并让这个颜色在玩家社区里可被口口相传（"找蓝色的那个"比"点第三个标签"更好传达）。

### 原则 4：用「世界内的物件」当按钮，把拟物做到物件层而不是控件层
**证据**：暖帘 → 里屋；木头 → 准备行李；布包 → 商店；房子 → 进屋。这些都是**场景里本来就该存在的东西**，不是"套了木纹边框的按钮"。[1][4][8][11]
**迁移方法**：先问"这个功能在这个场景里对应什么实体"，再把它画成可点击的物件。避免"木质纹理 + 圆角矩形 + 图标"这种假拟物。

### 原则 5：状态标记要像"贴上去的标签"，而不是"系统弹窗"
**证据**：商店里已购买的非消耗品显示**红色「售罄」标签**（纸片感），而不是灰掉/加锁图标/弹窗。[10]
**迁移方法**：状态变化优先用"在物件上贴一张小纸片"表达，保持世界内的材质一致性。

### 原则 6：只在拇指可达区放控件，让中央与上部保持"不可交互"
**证据**：所有功能按钮都在左下/右下/右上角；画面中央与上部只有青蛙、のれん 这类"世界内物件"。[1][4][8]
**迁移方法**：不要为了布局好看把按钮往上铺。反过来，**把顶部区域让给画面**，是同时解决单手操作与画面完整性的方法。

### 原则 7（慎用）：把"等待"做成核心体验——延迟反馈 + 随机奖励 + Push 通知
**证据**：点击不产生即时奖励；奖励以明信片/特产/回家形式延迟且随机出现；玩家无法影响青蛙行踪；单次旅行最长约 4 天；开发者自述这是**"玩家被放置"**的游戏，用"思念"形成互动。[16][18]
**迁移方法**：只在**情感陪伴类**产品里可以这么干。它的收益是"把游戏嵌进真实生活"，代价是**留存动力不足、缺成就感/社交/挑战**——原版本身就因此被分析为"后期动力不足"。[18]
**不能照搬的理由**：这需要玩家接受"我无法控制"这一前提。任何带目标、带养成、带进度的游戏直接用会变成"手感差"。

### 原则 8（慎用）：原作的克制是"全系统一致"的结果，不能只抄 UI 层
**证据**：所有攻略与评测都指出，本作没有任务、没有关卡、没有成就、没有社交、没有排行榜，**只有三叶草一种资源兼行动力**。[1][2][18]
**证据**：中国版加了"任务/活动/商城"三块之后，界面结构和节奏感都明显偏离原版。[19][20]
**迁移方法**：原则 1–6 只有在**没有红点、没有日常任务、没有限时活动**的前提下才成立。一旦加了这些，主界面必然被横幅和角标占满，"一幅画"就守不住了。
**结论**：原则 1–6 可以抄，**但必须同时承诺"不加红点体系"**；否则只是给一个有红点的游戏套了层插画皮，两边都不讨好。

## 11. 本次调研的局限（务必阅读）

1. **网络抓取受限**：本次调研中 **WebFetch 工具对该环境下所有目标域名均被安全策略拦截**（含 wikipedia、hit-point 官网、各大中文媒体、攻略 Wiki、知乎等），因此**所有内容均来自搜索引擎返回的摘要**，未能逐一打开原文核对，也**未能取得任何界面截图**。
2. **搜索配额耗尽**：WebSearch 配额（200 次）在调研中途用尽，因此第 5 问（文字层级）与第 7 问的部分细节**查证不足**。
3. **因此以下结论请当作待验证**：
   - 第 5 问的字号层级、字体族、文字描边/底板 —— **基本空白，仅有推断**。
   - 第 7 问的点击视觉反馈、转场动画、加载动画 —— **基本空白，仅有推断**。
   - 主场景按钮的精确位置（特别是"菜单在庭院还是室内"）—— **来源互相冲突，标为存疑**。
   - 三叶草生长速率 —— **两个来源冲突（4 分钟/个 vs 3 小时长满）**。
4. **建议的补证方式**：直接看游戏截图或录屏（App Store / Google Play 商店页截图、B 站/YouTube 实况），即可一次性确认第 5、7 问以及按钮布局的全部空白项。

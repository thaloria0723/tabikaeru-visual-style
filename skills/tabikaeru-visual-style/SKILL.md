# 旅行青蛙式视觉风格

## 核心判断（先读这一条）

**这套画面的「安静」不来自画法，来自减法。**

画法本身平平无奇——就是商业扁平矢量插画（flat vector illustration）。让它与众不同的是画法之上的一整套减法决策：**删表情、删饱和、删暗部、删特效、删主体面积**。

由此推出本 skill 最重要的一条禁令：

> **不要用「加东西」来模仿这个风格。** 加纸纹、加水彩笔刷、加噪点颗粒、加暗角、加光晕——全部是南辕北辙。实测证据：原作平坦区 40×40 像素块亮度标准差 **SD=0.00**，单条水平方向连续 **163pt** 为完全同一个色值。**任何纹理叠加层都会破坏这个风格的地基。**

如果你发现自己正在「加点质感让它更像」→ 停下。你在反方向走。

## 三条硬规矩

这三条不是风格问题，是**防止你输出看似专业实则无依据的内容**。每一条都对应一个真实观察到的失败模式。

### 规矩一：每个数字必须带来源标签

任何出现在产出里的数值（色值、时长、比例、百分比），必须标三选一：

| 标签 | 含义 |
|---|---|
| 【实测】 | 从真实参考物测量得到，可复现 |
| 【推导】 | 从【实测】的约束区间算出来的 |
| 【自定】 | **你自己的设计决定**，无外部依据 |

**禁止把【自定】呈现为【实测】或【推导】。**

为什么：观察到的失败模式是——色值全是编的、时长全是自造的，却被写成「推导结果」，读者无法分辨哪些能信。这比没有数字更糟，因为它让人以为有依据。

### 规矩二：不许出现「伪参数」

一个数值只有在**有人能验收它**的时候才允许写成数值。

- ✅ 「明亮度中位数 ≥ 0.75」——可以写脚本测，能验收
- ✅ 「圆角 12rpx」——前端能实现，能验收
- ❌ 「干边深度 8–12%」——前端实现不了，原画验收不了，**这是给形容词穿了数字外衣**
- ❌ 「纸纹颗粒度 0.3」——同上

**自检问句：这条数字，是谁来验？怎么验？答不出来就改写成散文。**

**追加一条：禁止用【自定】验证【自定】。**

实测观察到的失败模式：先自己定一套「面积预算」（各色占屏百分比），再用它去「验证」色板合规——**这是循环论证，两条都是自定的，互相证明不了任何事。**

- 【自定】的面积预算**只能当地约束**，不能当验收依据
- 真要验收色板合规，必须**画一张图跑直方图**，那是【实测】
- 凡是用自定参数推出的结论，必须显式标注「这是预测，不是测量」

### 规矩三：反例清单比正面规范更优先

这个风格的定义，一半靠「不做什么」。写产出时**先写减法清单再写加法清单**。

```
   （量级）        （不抄原作的色值）      （见 references）     （见 references）
```

### ① 定约束区间

不要凭感觉定，用实测区间做包络（完整表见 `references/measured-reference.md`）：

| 维度 | 目标区间 | 原作实测 |
|---|---|---|
| 明亮度中位数 | ≥ 0.75（高明调） | 0.77–0.89 |
| 饱和度中位数 | ≤ 0.35 | 0.17–0.35 |
| 高饱和像素（S>0.60）占比 | ≤ 2% | 0.5–1.4% |
| 近灰像素（S<0.10）占比 | ≥ 15% | 18.9–22.0% |
| 线＋暗部覆盖率 | ≤ 20% | 6.35–19.20% |
| 主角占屏面积 | ≤ 3% | 0.49% |
| 最大单色平涂块占屏 | ≥ 35% | 43.2% |

**这组区间是可以直接搬的**——它们是通用技法约束，不构成抄袭。

> ⚠️ **验收时必须同类比同类。** 实测踩到的坑：用一组几何色块拼的简版画面去代这组区间，「近灰占比 S<0.10」只拿到 14.88%（目标 ≥15%），差 0.12 个百分点。
> 原因不是色板不合格，而是**这项指标由画面构成主导**——原作的 18.9–22.0% 是在**内容复杂的完整游戏截图**上测的，而简版画面只有 4 个形状、大面积被单一暖色占据，冷灰中性的绝对面积天然更小。
> **所以：这组区间用于对照「同等复杂度的画面」。** 拿一张色卡或简版 demo 去代，结果偏保守是正常的，不要为了凑指标去改配色——那是把验收变成了刷分。

### ② 生成自己的色板

**关键：不要沿用原作的色值组合。**

砂米 `#D8D0A8` + 冷灰 `#B8BFC5` + 蛙绿 `#7EAA51` + 墨 `#505F4C` 这一组，已经被玩家反复观看、被媒体反复定义，**是该 IP 的视觉签名**。照搬这一组，你做的不是「借鉴风格」，是「抄那个游戏」。

正确做法——**保留结构关系，换掉具体色值**：

1. **一个暖中性底色**（占画面最大面积，明度 0.80–0.90，饱和 0.15–0.25）
2. **一个冷中性对比色**（几乎无彩，S<0.10，用来做冷暖对比——原作是靠「暖褐 vs 冷灰」这一组近中性色完成对比的，**不是靠色相撞色**）
3. **一个低饱和的品牌／记忆色**（饱和 0.45–0.60，占屏极小，是角色的颜色）
4. **一支墨线色**：暗浊、非黑、非棕。选一个明度 0.35–0.45、饱和 0.10–0.25 的暗色
5. **2–3 个点缀色**：占比各 <2%

**然后验证**：把你生成的所有色值代进 ① 的区间表，任何一条不满足就回去调。

> 交大项目的落点：交大红是最强的记忆色候选，但它饱和度过高，**只能进「点缀色」档（<2% 占屏）**，不能当底色。底色从校园的暖中性色里取（老建筑墙面、梧桐、纸、石材）。

## 减法清单（去糖清单）

**这八条是风格的真正来源。** 每一条都有实测依据。

| # | 删什么 | 为什么 |
|---|---|---|
| 1 | **眼睛的高光、瞳孔、眼白** | 只留一个实心色块。可爱角色通常靠「大眼睛＋高光＋腮红」生产甜度，删掉这三样，读出来的就是「平静」而不是「讨好」 |
| 2 | **腮红、星星眼、睫毛** | 同上，甜度来源 |
| 3 | **高饱和色** | 高饱和像素占比压到 2% 以下。画面里几乎不存在「兴奋色」 |
| 4 | **纯黑** | 全场零纯黑。最暗像素亮度约 42–66/255，墨线用暗浊彩色 |
| 5 | **角色和道具的投影** | 靠勾线分离物体。**只有 UI 面板允许软投影**——这是一个刻意的分层 |
| 6 | **连续渐变** | 全画面平涂硬边。唯一例外：需要表达「另一种媒介」的图（如照片）允许单调连续渐变 |
| 7 | **弹窗的背景压暗遮罩（scrim）** | 绝大多数手游都会加，原作不加。这是维持全画面高明调的关键 |
| 8 | **全屏纹理／噪点／暗角／粒子／魔法光效** | 见核心判断。加这些等于自毁地基 |

**还有一条构图上的减法**：把主角画小。主角占屏 <1%，大面积让给「空」。可爱风游戏通常放大主角强化萌感，这里反着来——这是「克制」在构图层的体现。

**注意**：「留白」是**同色系的大面积平涂**，不是白色。原作的大面积「空」是暖砂色、暖灰褐、冷天蓝——有颜色、有温度。这是「安静」而不「冷清」的原因。

## 当风格与可读性冲突时

这套风格里，「安静」的**技术载体之一就是低对比**（原作墨色对底色只有约 5:1）。所以一旦场景要求高可读性——老年用户、强光下使用、小屏远看——**冲突是真实的，不是可以调和的。**

**错误的解法是折中**（对比度取个中间值），结果是两边都不成立。

**正确的解法是把「安静」的载体整体搬走**：低对比这一项牺牲掉，改由这些来承担安静感——

- 大面积平涂
- 低元素密度
- 大间距
- 少颜色
- 暖色留白（不是白）
- 平涂硬边、零渐变、零纹理

风格的结构性手法几乎全部保留，只换掉「低对比」这一根支柱。

**推论**：如果场景需要加深墨色，**先看它有没有掉出参考物自身的最暗端**。原作最暗像素亮度是 **42–66/255**——把文字墨压到通道最大值 55/255 左右，**不是破坏风格，是回到参考物自身的最暗端**。这是个比「凭感觉调深」有依据得多的锚点。

## 常见错误

| 错误 | 为什么错 | 怎么改 |
|---|---|---|
| 加纸纹／水彩笔刷／噪点让它「更有质感」 | 实测 SD=0.00，原作根本没有全屏肌理层 | 删掉。肌理只能是**局部绘制的低对比笔触**（亮度差 6–12%，软边），且只出现在木、石、叶、水等需要交代材质的对象上 |
| 把绿色当画面主色 | 实测覆盖率最高的是砂米和冷灰，绿色只是角色色 | 底色用暖中性，绿色降级到记忆色档 |
| 用黑线勾边 | 全场零纯黑 | 换一支暗浊彩色墨线，明度 0.35–0.45 |
| 每条线用不同的颜色（按物体变色） | 原作**线色不随填充变化**——粉底和白底共用同一支墨 | 全项目共用一支墨色 |
| 给角色加投影让它「站稳」 | 原作角色无投影 | 删掉，靠轮廓线分离 |
| 弹窗加半透明黑遮罩 | 原作不加 | 删掉，保持背景全亮度 |
| 主体画大以强化萌感 | 主角占屏 0.49% | 画小，让给空 |
| 写一堆无法验收的数值 | 见规矩二 | 要么能被验收，要么改散文 |

## 危险信号

发现自己正在做这些 → 停下：

- 正在往画面上加一层纹理／噪点／纸感
- 正在写「干边深度 15%」「颗粒强度 0.4」这类没人能验收的数字
- 正在把自造的时长／色值／比例写成「推导结果」
- 正在直接使用 `#D8D0A8` `#B8BFC5` `#7EAA51` `#505F4C` 这一组原作色值
- 正在用「温馨治愈有呼吸感」这类形容词代替具体决策
- 正在为了「看起来完整」而填写没有数据支撑的章节
- 正在用自己定的参数去「验证」自己定的另一组参数
- 正在照抄参考文件里的示例值而不检查它是否适配你的场景（示例值可能带单位/量纲错误）

## 完成标志

- [ ] 产出里每个数值都带【实测】/【推导】/【自定】标签，且没有标签误用
- [ ] 没有「伪参数」——抽查任意三个数值，都能回答「谁来验、怎么验」
- [ ] 色板是**自己生成的**，不是原作色值组合
- [ ] 生成色板已代回约束区间表验证通过
- [ ] 减法清单八条已逐条确认
- [ ] 没有添加任何全屏纹理／噪点／暗角
- [ ] 如写了 CSS：无渐变、无纯黑、角色无投影、弹窗无遮罩
- [ ] 如写了生图提示词：负面词包含那 8 项
- [ ] 查不到的信息**标注为缺口**，没有编造

# tabikaeru-visual-style

An agent skill for the 《旅行青蛙》/ 旅かえる (Tabikaeru) visual language — quiet flat fills, a single non-black ink outline, a high-key low-saturation palette, and deliberate subtraction.

《旅行青蛙》视觉风格的 agent skill——低饱和平涂、单支非黑墨线、高明调色板，以及一整套减法决策。

---

## 核心判断

**这套画面的「安静」不来自画法，来自减法。**

画法本身平平无奇——就是商业扁平矢量插画。让它与众不同的是画法之上的一整套减法决策：删表情、删饱和、删暗部、删特效、删主体面积。

由此推出最重要的一条禁令：**不要用「加东西」来模仿这个风格。** 加纸纹、加水彩笔刷、加噪点颗粒、加暗角——全部是南辕北辙。

> 中文圈普遍把它当作水彩／和纸风格。逐像素实测否定这一点：平坦区亮度标准差 **SD=0.00**，单条水平方向连续 **163pt** 为完全同一个色值。**原作根本没有全屏肌理层。**

## 它是怎么来的

不是凭印象写的。过程：

1. **取到 5 张官方 App Store 截图**（Hit-Point 官方，`id=1255032913`，v1.9.2），PNG 1242×2208 RGB 无损，经 iTunes Lookup API 取得
2. **逐像素解码测量**——自写 PNG 解码器，不依赖目测或记忆。色值、覆盖率、亮度标准差、线宽全部可复现
3. **跑基线**：先让模型在没有任何风格参考的条件下写一份「旅行青蛙风格 UI 说明」，记录它犯的错
4. **按失败模式写 skill**，再用 3 个场景（原任务 / 时间压力 / 跨领域变体）验证迭代

完整调研报告在 [`research/`](research/)，含来源清单与证据分级——**这些数字是量出来的，你可以验。**

## 它最有用的部分

### 三条硬规矩

skill 里强制任何产出遵守：

1. **每个数值必须带来源标签**——【实测】/【推导】/【自定】，禁止把自定的说成实测的
2. **不许「伪参数」**——每个数字都要能回答「谁来验、怎么验」，答不出来就改写成散文
3. **反例清单优先于正面规范**

### 减法清单（去糖清单）

八条，每一条都有实测依据。例如：删掉眼睛的高光／瞳孔／眼白（只留一个实心色块）、删掉角色投影、删掉弹窗的背景压暗遮罩、**删掉全部高饱和色**（原作饱和度 >0.60 的像素仅占 0.5–1.4%）。

### 「抄约束，不抄结果」

skill 明确区分**可复用的通用技法**与**照搬即抄袭的 IP 签名**——后者包括原作那组具体色值、木牌式 UI 形态、青蛙母题。

正确做法是保留结构关系（暖中性底 + 冷中性对比 + 低饱和记忆色 + 一支暗浊墨线）而**换掉具体色值**。

## 已知限制（请不要盲信）

- **生图提示词那部分是【推导】未验证的。** 写它的时候没有可用的图像生成器跑 A/B。词表结构有依据，具体权重和措辞需要你用实际模型调。第一轮出图后欢迎提 Issue 反馈偏差。
- **夜间场景零样本。** 样本内没有夜间截图，所以「夜晚是否压暗／压暖、有无光晕」**没有答案**，skill 里明确标注为缺口、不作答。
- **季节配色零样本。** 知存在（官方有季节更新），但取不到素材，因此**没有编造色值**。
- **游戏内具体字体名查不到。** 中日英多组检索均无结果。**没有猜。**
- **头身比未精确测量**，仅目测，skill 里标为弱证据。
- **原作的动效 / 转场 / 点击反馈零样本**（静态截图），因此不在本 skill 范围内。

## 适用边界

**适用**：低饱和、高明调、扁平插画、安静克制的视觉方向；色板推导；CSS design tokens；生图提示词。

**不适用**：3D、像素画、高饱和卡通、厚涂／写实。

**一个真实的冲突值得提前知道**：这套风格里「安静」的技术载体之一就是**低对比**。所以一旦场景要求高可读性——老年用户、强光下使用、小屏远看——冲突是真实的。skill 里给了处理方式：**不是折中，而是把「安静」的载体整体搬走**（改由大面积平涂、低元素密度、大间距承担），并给了「参考物自身最暗端」作为加深墨色的锚点。
